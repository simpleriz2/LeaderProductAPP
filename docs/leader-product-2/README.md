## ADR-008: explicit unreleased module compatibility format
Accepted: manifest **format2** replaces the local, never deployed format1 prototype; old formats fail closed. Each artifact must declare `requires.minHost`, exact native capability revisions and exact semantic port versions. Host context supplies explicit supported revision/version sets plus supported exported module contracts. Higher revision alone never implies backwards compatibility. Shared runtime family remains an independent compatibility gate; source fingerprint identifies the actual APK/bundle pair. Signed metadata cannot make unavailable native code appear. Empty requirements on QR/Help probes describe delivery fixtures only, not working camera/chat features.
No deployed/offline client exists on these prototype formats. Future deployed format evolution must retain an explicit offline compatibility window/migration path; rejecting local format1 is not a production update strategy. Business API compatibility and key rotation remain separate backlog items.

## Bootstrap and session-bound release activation
Core now exposes bootstrapRelease: online assignment is checked before working-module startup; unchanged signed sets verify existing files/data without copying data; offline uses only the caller's already confirmed session lease and verifies every saved signature/file/data generation. First offline installation requires network. Compatible code LKG recovery keeps the current data generation and new edits; incompatible schema, damaged data or untrusted metadata leads to recovery without restoring an old database. UI/real domain SDK integration remains pending.
Every asynchronous release continuation is checkpointed against the login/logout/revoke/account-switch lease, including entirely cached updates and progress callbacks. Late old-account commit may leave a valid old-account pointer, but cannot return ready into another account. LKG is now explicitly confirmed after a host-supplied startup health check; candidate activation/recovery preserves the last confirmed checkpoint. Actual selected-module health integration remains pending with the trusted loader.

## ADR-009: candidate activation and healthy checkpoint are separate
Accepted: commit installs a candidate atomically but preserves the last explicitly confirmed healthy release. confirmReleaseHealthy verifies installed files/data, awaits actual host/module startup health, rechecks session and CAS-confirms the same candidate. A failed startup, logout or newer activation cannot replace LKG. Runtime recovery uses the confirmed code with CURRENT compatible data and returns restartRequired:true; no hot replacement of an executing module set. Native releaseStorage contract2 / APK versionCode4 implements this distinction. Earlier local prototype pointer records retain active code/data but their unconfirmed LKG is ignored on read; unknown storage formats fail closed. No original business migration/data is deleted.
Offline fallback after an entitlement-set change still needs acceptance beyond equal entitlement fixtures: never execute a revoked module, retain its private drafts, and determine an authorized coherent subset or recovery without restoring obsolete rights. This is unfinished stage1/3 work, not waived parity.
