## ADR-015: Web saved authority is revisioned across tabs
Web signed-proof storage now holds a monotonic revision and logout tombstone in one strict IDB transaction. Auth captures a confirmation ticket BEFORE its Central request; saving the returned signed proof CAS-checks that captured revision under a same-origin exclusive Web Lock. A late login/refresh cannot overwrite another tab's login/logout. Earlier local string-form signed proofs remain readable and acquire a revision at the next durable change; malformed records fail.
Bounded protected data/HTTP/outbox work can hold store.run's shared session-authority lock, verify exact current signed identity/rights and reject stale results on abort. Required lock order is session authority THEN account generation/data lock; confirmation/persistence occurs outside protected work. Do not hold this lock for socket lifetime/unbounded polling. Actual SDK/router/worker composition remains the next integration step; exposing this port alone does not fence every existing operation.
BroadcastChannel carries only a change hint. Binding re-reads verified durable authority, aborts the captured local lease and tears resources down via coordinator.invalidateExternalSession without clearing another tab's proof. A delayed/missed hint cannot authorize work through store.run because it checks durable authority. Disposing the binding prevents an in-flight callback from invalidating a newer local lease. Product UI must hide old screens on invalidation and handle unsaved state; current tests use lifecycle probes. Native multi-process authority coordination remains separate.
